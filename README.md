# Защищённый REST API — лабораторная работа № 1

Учебный backend на Flask демонстрирует защиту от SQL-инъекций и XSS, JWT-аутентификацию,
безопасное хранение паролей и автоматические проверки безопасности в GitHub Actions.

## Возможности API

| Метод | Маршрут | Назначение | Доступ |
|---|---|---|---|
| `GET` | `/health` | Проверка работоспособности | публичный |
| `POST` | `/auth/login` | Получение JWT по логину и паролю | публичный |
| `GET` | `/api/data` | Получение защищённых данных | JWT |
| `POST` | `/api/notes` | Создание заметки | JWT |
| `GET` | `/api/notes` | Список заметок пользователя | JWT |

## Реализованные меры защиты

### SQL-инъекции

Все значения передаются в SQLite отдельно от текста SQL через плейсхолдеры `?`. Строковая
конкатенация для формирования запросов не используется. Тест с логином `' OR 1=1 --` проверяет,
что классическая SQL-инъекция не позволяет войти.

### XSS

API отвечает с типом `application/json`, проверяет тип и длину входных значений и экранирует
пользовательские строки функцией `html.escape()` перед возвратом клиенту. Заголовок CSP запрещает
загрузку и исполнение контента. Автотест проверяет экранирование `<script>` и опасного `<img>`.

### Аутентификация и пароли

- пароли хэшируются `bcrypt` с уникальной солью и коэффициентом стоимости 12;
- ответы входа не раскрывают, существует ли пользователь;
- JWT подписывается HS256 и содержит `sub`, `iat`, `exp`, `iss`, `aud`, `jti`;
- middleware проверяет подпись, срок действия, издателя, аудиторию и пользователя;
- секрет JWT поступает только из переменной окружения и не хранится в Git;
- защищённые ответы получают заголовок `Cache-Control: no-store`.

## Локальный запуск

Требуется Python 3.12 или новее (в CI используется Python 3.12). Нижняя граница версии `click`
зафиксирована на 8.3.3, поскольку предыдущие версии затронуты CVE-2026-7246.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
export JWT_SECRET="$(python -c 'import secrets; print(secrets.token_hex(32))')"
flask --app app init-db
flask --app app run
```

Команда `init-db` запросит логин и надёжный пароль. Пароль должен содержать не менее 12 символов,
буквы обоих регистров, цифру и специальный символ.

## Проверка через curl

Получение токена:

```bash
curl -s http://127.0.0.1:5000/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"student","password":"YOUR_PASSWORD"}'
```

Скопируйте значение `access_token` в переменную:

```bash
export ACCESS_TOKEN='PASTE_TOKEN_HERE'
curl -s http://127.0.0.1:5000/api/data \
  -H "Authorization: Bearer $ACCESS_TOKEN"
```

Создание заметки:

```bash
curl -s http://127.0.0.1:5000/api/notes \
  -X POST \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -d '{"title":"Первая заметка","content":"Безопасный текст"}'
```

Проверка запрета доступа без JWT:

```bash
curl -i http://127.0.0.1:5000/api/data
```

Ожидается статус `401 Unauthorized`.

## Тесты и проверки безопасности

```bash
python -m pytest -q
bandit -r app
pip-audit -r requirements.txt
```

Workflow `.github/workflows/ci.yml` запускается при каждом `push` и `pull_request`, выполняет тесты,
SAST через Bandit и SCA через pip-audit. JSON-отчёты публикуются как artifact `security-reports`.
