# Dragon Keepers API — защищённый реестр всадников и драконов

Лабораторная работа № 1 по дисциплине «Информационная безопасность».

Dragon Keepers API — учебный backend на Flask. Каждый пользователь выступает в роли всадника:
после аутентификации он получает JWT и может просматривать только собственную коллекцию драконов
или добавлять в неё новых существ. Проект демонстрирует защиту от SQL-инъекций и XSS, безопасное
хранение паролей и автоматические security-проверки в GitHub Actions.

## Сценарий

В системе есть две связанные сущности:

- **всадник** — учётная запись с логином и bcrypt-хэшем пароля;
- **дракон** — запись с именем, видом, стихией, возрастом и описанием, принадлежащая конкретному
  всаднику.

JWT связывает запрос с всадником. SQL-запрос `WHERE rider_id = ?` не позволяет одному всаднику
получить коллекцию другого даже при обращении к тому же маршруту.

## Методы API

| Метод | Маршрут | Назначение | Доступ |
|---|---|---|---|
| `GET` | `/health` | Проверка работоспособности | публичный |
| `POST` | `/auth/login` | Авторизация всадника и получение JWT | публичный |
| `GET` | `/api/data` | Получение коллекции текущего всадника | JWT |
| `POST` | `/api/dragons` | Добавление дракона в свою коллекцию | JWT |

Таким образом, обязательный маршрут `GET /api/data` возвращает не абстрактный набор данных, а
полноценную предметную коллекцию.

## Формат дракона

```json
{
  "name": "Буревестник",
  "species": "Грозовой дракон",
  "element": "storm",
  "age": 42,
  "description": "Разведчик северной эскадрильи"
}
```

Допустимые стихии: `fire`, `ice`, `storm`, `earth`, `shadow`, `light`.

## Реализованные меры защиты

### Защита от SQL-инъекций

Все значения передаются в SQLite отдельно от текста SQL через плейсхолдеры `?`. Конкатенация
пользовательского ввода с SQL не используется. Автотест с логином `' OR 1=1 --` подтверждает, что
классическая SQL-инъекция не позволяет войти.

### Защита от XSS

API принимает только JSON, проверяет тип, диапазон и длину каждого поля дракона, а строки перед
возвратом экранирует функцией `html.escape()`. Ответы имеют тип `application/json`. Заголовок CSP
запрещает загрузку и исполнение активного содержимого. Автотест отправляет `<script>` и опасный
`<img>` и проверяет, что они возвращаются только в экранированном виде.

### Аутентификация и разграничение доступа

- пароли хэшируются `bcrypt` с уникальной солью и коэффициентом стоимости 12;
- ошибка входа не раскрывает, существует ли всадник;
- JWT подписывается HS256 и содержит `sub`, `iat`, `exp`, `iss`, `aud`, `jti`;
- middleware проверяет подпись, срок действия, издателя, аудиторию и существование всадника;
- каждая операция с драконами фильтруется по идентификатору всадника из проверенного JWT;
- отдельный тест подтверждает, что чужой дракон не попадает в коллекцию текущего всадника;
- секрет JWT задаётся переменной окружения и не сохраняется в Git;
- ответы получают `Cache-Control: no-store` и другие защитные заголовки.

## Локальный запуск

Требуется Python 3.12 или новее. В CI используется Python 3.12.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
export JWT_SECRET="$(python -c 'import secrets; print(secrets.token_hex(32))')"
flask --app app init-db
flask --app app run
```

Команда `init-db` запросит логин и надёжный пароль всадника, создаст базу и добавит двух тестовых
драконов — Искру и Севера. Пароль должен содержать не менее 12 символов, буквы обоих регистров,
цифру и специальный символ.

## Проверка через curl

### 1. Авторизация всадника

```bash
curl -s http://127.0.0.1:5000/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"student","password":"YOUR_PASSWORD"}'
```

Скопируйте значение `access_token`:

```bash
export ACCESS_TOKEN='PASTE_TOKEN_HERE'
```

### 2. Получение коллекции драконов

```bash
curl -s http://127.0.0.1:5000/api/data \
  -H "Authorization: Bearer $ACCESS_TOKEN"
```

### 3. Добавление дракона

```bash
curl -s http://127.0.0.1:5000/api/dragons \
  -X POST \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -d '{
    "name":"Буревестник",
    "species":"Грозовой дракон",
    "element":"storm",
    "age":42,
    "description":"Разведчик северной эскадрильи"
  }'
```

### 4. Проверка запрета доступа

```bash
curl -i http://127.0.0.1:5000/api/data
```

Ожидается статус `401 Unauthorized`.

## Тесты и security-сканеры

```bash
python -m pytest -q
bandit -r app
pip-audit -r requirements.txt
```

Workflow `.github/workflows/ci.yml` запускается при каждом `push` и `pull_request`, выполняет тесты,
SAST через Bandit и SCA через pip-audit. JSON-отчёты публикуются как artifact `security-reports`.

## Что показать в отчёте

1. Успешную авторизацию всадника; значение JWT нужно замазать.
2. Ответ `401` на запрос коллекции без токена.
3. Коллекцию из двух драконов после запроса с JWT.
4. Добавление Буревестника и обновлённую коллекцию.
5. Результаты автотестов, Bandit и pip-audit.
6. Успешный workflow GitHub Actions.

Не публикуйте реальные пароли, секрет JWT, действующие токены и файл базы данных.
